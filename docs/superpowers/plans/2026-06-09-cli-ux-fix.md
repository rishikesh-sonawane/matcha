# CLI UX Fix Implementation Plan

> **For agentic workers:** Required sub-skill: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate terminal display corruption and ensure the CLI shows clean Rich output without log interleaving, with prompt termination, and with progress indication during AI phases.

**Architecture:** Route all logging to file only so Rich's Live/Progress display is never corrupted by stderr log lines. Suppress noisy third-party library loggers. Add dirty-state tracking to the status table to prevent unnecessary re-renders. Increase AI query generation `max_tokens` so the prompt response isn't truncated. Use `os._exit(0)` in `main()` to kill orphaned `ddgs` library threads that would otherwise prevent process exit.

**Tech Stack:** Python 3.14, Rich (Live, Progress, Table, Prompt), logging, concurrent.futures, ddgs library, primp HTTP client.

### Task 1: Route all logging to file only

**Problem:** `logging.basicConfig` includes a `StreamHandler(sys.stderr)` that writes log lines to stderr. Rich's `Live` display writes to the terminal. When both write in the same tick, lines interleave, corrupting the display. The `logging.handlers` submodule also requires explicit `import logging.handlers` in Python 3.14.

**Files:**
- Modify: `main.py:44-56`

- [x] **Step 1: Remove `StreamHandler` from logging config**

Old code:
```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.handlers.RotatingFileHandler(
            Path.home() / ".matcha" / "logs" / "matcha.log",
            maxBytes=5_000_000,
            backupCount=3,
        ),
        logging.StreamHandler(sys.stderr),
    ],
)
```

New code:
```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.handlers.RotatingFileHandler(
            Path.home() / ".matcha" / "logs" / "matcha.log",
            maxBytes=5_000_000,
            backupCount=3,
        ),
    ],
)
```

- [x] **Step 2: Suppress noisy third-party loggers**

Insert after `logging.basicConfig`:
```python
for _lib in ("primp", "httpx", "ddgs", "urllib3"):
    logging.getLogger(_lib).setLevel(logging.WARNING)
```

- [x] **Step 3: Verify only `RotatingFileHandler` exists on root logger**

Run:
```bash
venv/bin/python -c "
import main
import logging
for h in logging.root.handlers:
    print(type(h).__name__)
"
```
Expected output: `RotatingFileHandler` (no `StreamHandler`)

### Task 3: Reduce status table flicker with dirty-state tracking

**Problem:** `live.update(_status_table())` is called on every `as_completed` iteration. When multiple scrapers complete in rapid succession, the table re-renders with identical content many times, creating visual noise.

**Files:**
- Modify: `main.py:214-232`

- [x] **Step 1: Add state comparison before update**

In the `as_completed` loop, before updating, serialize current state and compare to previous:

```python
_last_state: Optional[tuple[bytes, ...]] = None
try:
    for future in as_completed(futures, timeout=45):
        source_name = futures[future]
        _, result = future.result()
        pending[source_name] = False
        if result.errors:
            source_errors.setdefault(source_name, []).extend(result.errors)
        unique = deduplicate(result.jobs)
        source_counts[source_name] = source_counts.get(source_name, 0) + len(unique)
        all_jobs.extend(unique)
        _state = (str(pending).encode(), str(source_counts).encode(), str(source_errors).encode())
        if _state != _last_state:
            live.update(_status_table())
            _last_state = _state
        time.sleep(0.05)
except TimeoutError:
    logger.warning("Scraper batch timed out after 45s, returning partial results")
    live.update(_status_table())
```

### Task 4: Force clean process exit

**Problem:** The `ddgs` library creates its own internal threads (primp HTTP client, async loop) that are non-daemon. After `search_jobs` returns, these threads keep running for 60-90+ seconds, preventing the Python process from exiting.

**Files:**
- Modify: `main.py:734-745`

- [x] **Step 1: Add `os._exit(0)` after normal run completion**

Replace:
```python
def main() -> None:
    try:
        run()
    except Exception:
        logger.exception("Unhandled exception in main")
        console.print("[red]An unexpected error occurred. Check logs for details.[/red]")
        sys.exit(1)
```

With:
```python
def main() -> None:
    try:
        run()
    except Exception:
        logger.exception("Unhandled exception in main")
        console.print("[red]An unexpected error occurred. Check logs for details.[/red]")
        sys.exit(1)
    os._exit(0)
```

Add `import os` at top of file if not present.

### Task 6: Non-blocking executor shutdown

**Problem:** `with ThreadPoolExecutor(...)` calls `shutdown(wait=True)` on exit, which blocks until all worker threads complete. After a batch timeout, this causes the function to hang while orphaned threads finish.

**Files:**
- Modify: `main.py:203-234`

- [x] **Step 1: Replace `with` with explicit lifecycle**

Old code:
```python
with ThreadPoolExecutor(max_workers=min(total_tasks, 12)) as executor:
    ...
```

New code:
```python
executor = ThreadPoolExecutor(max_workers=min(total_tasks, 12))
try:
    ...
finally:
    executor.shutdown(wait=False, cancel_futures=True)
```
